# CYBERSOS — PHASE 12
# Final demonstrated acceptance, operations and gated release decision

Read root AGENTS.md and [shared contract](README.md) completely. Inspect actual
Phase 11 environment and synthetic beta evidence. Do NOT add major features.

## End-user result and current scope

Claims reflect demonstrated capability. Under current free-tier/synthetic-only
authorization, this phase establishes final test acceptance and release readiness,
not a real-data/public release. No automatic launch, billing or provider-data change.

## Required acceptance

1. Freeze an evidence-backed support matrix for incident types/jurisdictions,
   languages, browsers/devices, voice, formats/extraction, return, reporting and
   handoff. Distinguish unsupported/untested from passed; no roadmap advertising.
2. For every declared incident, verify tell story once → grounded understanding
   → useful answers/investigation → attachments reduce effort → reviewed canonical
   facts → deterministic actions → current case sheet → revision-bound reporting
   packet → honest handoff → secure return/memory → deletion.
3. Reject fixed-questionnaire behavior, repeated first-send, duplicate questions,
   vanishing composer, empty/dashboard creep, giant review forms, stale plans,
   historical chat masquerading as current truth and projection disagreements.
4. Grade longer conversations, relevant/why questions, pause/skip, mixed intent,
   distress, corrections, older recall, conflicts and multiple incidents. Verify
   RAG source support/freshness, memory poisoning resistance, voice transcription
   corrections and multilingual action meaning. API 200 is not quality acceptance.
5. Confirm reviewed packet semantics and no fake submission. If a genuine official
   integration is discovered, document a separate critical-integration proposal;
   it is not automatically in scope for this no-major-features phase. Enabling it
   requires authorization, verified identity/auth, failures and real acknowledgements.
6. Re-run release-critical security/privacy, authorization, concurrency, retention,
   deletion, provider failures and deployment restoration/rollback acceptance.
7. Report measured synthetic-beta metrics as synthetic. Do not describe them as
   real citizen recovery, successful complaints or guaranteed response times.

## Operations and release gates

Define responsibility and procedures for model/provider changes, quotas, prompts/
schemas, source corpus review/withdrawal, memory/index migrations, playbook versions,
evidence policy, language review, privacy, security, secrets, backups/restore,
cost limits, deployment/rollback and support. Record unresolved blockers and owners;
if no actual operator is assigned, state the gap rather than inventing personnel.

Version prompts/model configuration and rerun the common evaluation set before
upgrades. Add source-expiry checks, provider-stage monitoring and a rollback route
for declining conversation quality; user-facing capability claims must follow scope.

Prepare a concrete release decision distinguishing final synthetic acceptance,
deployment readiness, privacy readiness and public-release authorization. Current
scope can finish test acceptance while public release remains unauthorized.

Only if later explicitly authorized and privacy/provider arrangements are suitable:
perform the reviewed release, run synthetic production smoke, and roll back on
critical failure. No paid infrastructure or real-data use is authorized by this prompt.

## Final report

Provide AGENTS.md completion report, actual support matrix, exact verification and
live stage evidence, measured limitations, operational runbook and release status.
Preserve chat-first UX, AI investigation, controlled actions, canonical case/memory,
reviewed reporting, truthful handoff and secure lifecycle. Do not call CyberSOS
released before all applicable gates pass. Stop at this phase boundary.
