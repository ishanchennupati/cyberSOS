# CYBERSOS — PHASE 11
# Reproducible deployment rehearsal and supervised synthetic beta

Read root AGENTS.md and [shared contract](README.md) completely. Prerequisite:
Phase 10 approved a defined test scope. Do NOT begin Phase 12.
Current authorization remains free-tier synthetic testing; no real citizen pilot.

## Required work

1. Inspect actual frontend/backend, DB/storage, memory/retrieval, model/speech
   providers, env/secrets, origins/domains, migration head, operational limits and
   expected cost. Do not deploy based on stale assumed services.
2. Carry unresolved prior issues forward. Resolve runtime/provider/security/browser
   limits or explicitly exclude affected capability from the test scope.
3. Prepare concrete reproducible deployment/migration/rollback configuration and
   procedures, with bounded free-tier usage, private access, secret handling and
   no paid fallbacks. Obtain explicit authorization before external deployment,
   provisioning or changes to accounts. Complete local preparation first.
   If hosting cannot meet the zero-spend constraint, report a local/staging-only
   rehearsal option; no purchase or fake deployed acceptance.
4. In the authorized environment, independently verify live fact extraction,
   conversational response/reasoning, RAG retrieval/claim support, evidence extraction,
   report drafting and speech where supported. One successful call is insufficient.
5. Across all three entry points and direct-story/Not sure bypass, run synthetic
   homepage → hybrid chat → contextual recommended replies/natural investigation/knowledge question
   → attachment → extraction/review → canonical merge → memory/current actions/case
   → reviewed packet/export/honest handoff → secure return → deletion.
6. Exercise quota, timeout, provider outage, retrieval failure, malformed output,
   network interruption and retry without bypassing validation or duplicating updates.
7. Establish privacy-safe stage error/latency/resource/quota metrics and estimate
   total case cost under potential future paid usage. No invented performance targets.
8. Rehearse backup, restore and rollback in the approved environment. Check private
   evidence consistency, migrations, summary/index freshness and revoked credentials
   after restore; restored backups must not silently undo deletion/revocation policy.
9. Conduct a small supervised synthetic beta: participants use invented scenarios,
   files and recordings only. Collect bounded consent-based feedback and grade
   useful help, repetition, misunderstandings, evidence corrections, report usefulness,
   abandonment, mobile/voice/language failures and provider limits.
10. Diagnose root causes and improve within existing scope. Reduce advertised scope
    when needed; no major new features or unsupported quality claims.

## UI verification

Verify actual deployment asset/API targets and all chat, artifact, recovery, language,
loading/error and mobile states. Preserve one consistent interface; explain testing
status honestly. Collect usability feedback on composer and optional evidence/review
controls without requiring participants to navigate technical workflows.

## Acceptance and limits

Provide actual environment, commands, stage results, restore/rollback evidence,
support matrix and failure exclusions. Supervised synthetic beta is not evidence of
real-world citizen outcomes. Real-data beta/public access needs new explicit
authorization plus suitable provider/privacy arrangements; free unpaid API terms
must be researched before any such change. No automatic Phase 12, spend or launch.
