# Step 0B implementation plan

**Goal:** consolidate existing evidence, mounted routes and migrations into one working contract without changing incident-response rules, wording or the guided UI.
**Spec:** the Step 0B user prompt (R1–R7), AGENTS.md and docs/audit.md. Prerequisite: 0A audit is recorded complete with passing documentation checks; its failing application baseline is explicitly accepted by the 0B repair prompt.
**Architecture:** one Evidence model in app/models/evidence.py and one upload route in api/routes/evidence.py. Existing services supply the frontend's missing readiness/description/template-summary operations. Alembic owns schema creation and additive legacy upgrades; startup does no DDL.
**Stack:** existing FastAPI/Pydantic/SQLAlchemy/Alembic, Next.js/TypeScript, pytest. No new AI integration or dependencies.
**Execution:** implement inline, test-first, on the existing phase-0 branch; proceed without an approval pause as the prompt requires. No commit/push/deploy/spending. Track progress here and final command evidence in docs/phase-status.md.

## Decisions and risks

- Retain the richer evidence contract already consumed by the frontend. Remove the legacy Evidence class, schema and service upload function rather than maintaining competing paths.
- Preserve existing incidents and legacy evidence metadata/file locations. Replace the mutable initial migration with explicit historical table/column definitions under the existing revision ID, then add a new consolidation revision so databases already at either old revision can upgrade.
- Support unversioned current startup-created schemas through the baseline's deliberate inspection/adoption of existing tables. Never silently stamp arbitrary databases; document the supported old schemas and migration command.
- Legacy SHA-256 was not stored. Backfill it only when the original local file exists under the configured prior evidence directory. Missing bytes leave hash unknown/null, never fabricated. New uploads always calculate SHA-256. Preserve original timestamps and private relative paths; configure LOCAL_STORAGE_ROOT to the old evidence directory before upgrades.
- SQLite and PostgreSQL DDL differ: use explicit named enums and batch column operations where needed; test SQLite locally and use a temporary local PostgreSQL instance if an installed server is available. Record unavailable production checks honestly.
- Missing cloud credentials select real local storage and existing deterministic providers. Do not implement new AI. Existing optional Anthropic code remains opt-in, missing-key/package fallback must work.
- Add nullable Incident bank/wallet/merchant/description because existing services and frontend need them; no inferred values or new mandatory fields.
- Implement readiness and description via existing service semantics, and summary via the existing deterministic template provider. No fake extraction/saving and no generated critical instructions.
- Return API-local preview URLs; the frontend resolves them against NEXT_PUBLIC_API_URL. Handle 204 deletion without JSON parsing.
- Keep R5 test isolation and frozen test clock independent: session-private migrated SQLite/storage, reset rows between tests, no root/backend test.db operations.
- Preserve all 0C wording/rule issues from the audit. Restored vault remains a synthetic-data prototype: this step does not establish real-data authorization/retention readiness.
