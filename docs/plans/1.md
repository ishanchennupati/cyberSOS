# Phase 1 implementation plan

Goal: typed deterministic financial response playbooks, retained versions and
private case isolation, while preserving the existing financial UI. Spec: the
Phase 1 prompt and AGENTS.md. Execute inline; no approval pause, commits or Phase 2.
Using writing-plans, test-driven-development and verification-before-completion.

## Decisions and boundaries

- Reuse Incident/Evidence ORM. Add typed domain models under app/domain, a central
  source registry and version-keyed playbook registry; no AI imports in engine.
- Discriminated facts distinguish authorized scam, unauthorized movement and
  explicitly unknown authorization. Optional booleans remain null. Provenance
  is typed and corrections retain immutable response-plan revisions.
- Playbooks own critical ordering and minimum facts. Reporting fields never gate
  containment/reporting. Unknown authorization uses common protective guidance;
  no unauthorized-liability advice is applied to approved scam transfers.
- Retain facts/schema/playbook versions and immutable plan snapshots per revision.
  Action completion references that revision and records only user self-report.
- Small capability design: 256-bit random token, SHA-256 hash + server expiry,
  constant-time check, HttpOnly/SameSite Strict per-case cookie; optional header
  for API clients. Secure cookies default on; local synthetic smoke explicitly
  disables Secure and keeps frontend/backend on localhost. Never URL/query tokens.
- Gate every current private route before services. Missing/wrong credentials and
  unknown resources share 404. Legacy cases without a capability stay locked;
  no public claim/reset endpoint. Existing legacy data is preserved, not inferred.
- Evidence policy enumerates prohibited content/credentials, rejects declared
  prohibited kinds and detectable secrets in text/metadata before storage. No
  claim that image moderation/OCR detects every prohibited file; no new extraction.
- Only financial playbooks are new. Existing nonfinancial handlers remain legacy
  and gain access checks; no new chat, providers, dashboards or other journeys.

Review risks: stale snapshot after fact correction; client-supplied source/AI
instructions; source-version drift; credentials on file previews; cookie cross-site
behavior; nullable unknown flags; legacy cases without honest historic versions;
image restrictions cannot be assured by byte signature alone.
